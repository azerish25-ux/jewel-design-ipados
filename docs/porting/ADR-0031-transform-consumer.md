# ADR0031: expandable transform consumer and owned profile data

Status: local native/source verification; source-specific Apple proof pending.

Admit seven exact TransformObject1.0 common headers (GUID27f4537a-6fc3-404f-9abd-eb53b7b3d8a1). Derived expandable class adds no binary fields. Independent Node reader records raw header/links and runtime sockets; structural writer preserves original arrays even when source load normalizes them.141 known headers/100 opaque/100 scalar handles. Future versions stay opaque.

LegacyTransformInputLayout replays source CSBlock.Read plus expansion creation. Begin with object and expansion sockets; valid object indices resolve with optional unchecked import offset, others become null/-1. If a saved index exceeds current runtime count, reuse an unlinked last socket or append after a linked one. HasLink requires object and nonnegative channel; Data can still have a negative output index. Final Read expansion creates/reuses the spare; NonExpandableInputChannels excludes it. Provider dependencies include every runtime socket, including a negative-index spare whose producer still needs scheduling.12285 cases compare exact extracted assignment/HasLink/creation bodies, with observation-only graph/channel constructors and source-class-cast/material side-effect limits.

For each non-spare transformation input, supported transform capability prepends to the product. Profile/rail data can supply transform capability in addition to curve geometry. Non-transformable scalar/empty data remain unchanged after duplication semantics; null object fails explicitly. Invalid matrix inputs are ignored. If a finite product overflows into nonfinite coefficients, source CSDataHelper.Transform skips application, so duplicate geometry/metadata remain unchanged. Complete invalid4x4/Unset equivalence still needs the full representation/original runtime.

Generated profiles own actual native transformed curves, immutable original group/index/name/sorted sweep parameters and cumulative transformation. CSProfileData prepends cumulative matrices; CSRailData through CSXformData and pure transform objects postmultiply them. Geometry itself always receives the composed transform on the left. Tests distinguish these noncommutative rules. Radius/scale rail metadata stays the source data value; it is not recomputed from deformed geometry. Selector forwarding retains owned aliases and all represented curve metadata. Native curve imports/outputs are disposed explicitly; retained readers survive replacement/disposal.

Original consumers115/122 use profile -> scale -> rotation -> translation -> placement;127 has a shorter profile -> scale -> placement chain. All three now generate actual native profiles. Native point checks apply each original input matrix sequentially rather than comparing a reused composed expression. Name/sweep bits/type capability, nested profile/rail/pure-transform order, edited/save/reopened geometry, selector snapshots, old readers, missing/empty/nonfinite/overflow/cycle and zero-entry cleanup pass. Four other saved consumers still reject missing one-rail/gem producers; none uses a preview or stored substitute.

CandidateProfileOutputInfo stores represented semantic metadata, not source material/bitmap/output flags or native pointers. No on-disk geometry cache or new serialized payload is invented. Curve tokens remain graph-local references; retaining native readers is explicit. Existing transactional failure-cache policy is not full original scheduler error equivalence.

Full BLD/SER acceptance remains open: arrays/recursive ownership, all other data capabilities, material/display/disabled/bitmap behavior, profile segmentation APIs/buffers, raw4x4/Unset/collapsed geometry, static/import scene side effects/class casts, one-rail/gems, all variants/full scheduler, renderer/export/UI/PC/iPad/PC/physical parity. The known non-array slice is an implementation step, not reduced final scope. No full parity row closes.
