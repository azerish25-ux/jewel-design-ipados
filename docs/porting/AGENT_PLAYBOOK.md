# Agent playbook

## Select one bounded task

Follow the dependency graph. Read the task, relevant source bodies and a bounded ledger slice. State requirement IDs, source methods, fixture hash, expected behavior, current failure, owned files and prerequisites. Split large cards into stable child IDs before coding; preserve parent acceptance criteria.

## Preserve versus replace

Record method provenance as unchanged, adapted, generated data or replacement. Do not rewrite pure CSharp merely to change language. Windows UI/kernel boundaries require real mobile implementations. A compiling user32/kernel32 declaration is not functioning reuse. Global line counts include variants, duplicates, data, annotations and service contracts; they are not progress percentages.

## Implementation cycle

1. Inspect code and fixtures; resolve ambiguity with a Windows oracle or record a blocker.
2. Add concrete normal, boundary and failure regressions; observe the expected failure first.
3. Implement one behavior change in production directories through genuine boundaries.
4. Run focused tests, adjacent regressions, platform tests and repository checks. Capture exact commands, expected/actual outputs and hashes.
5. Review the diff and outputs. Update only affected rows/evidence and commit with the task ID.
6. Handoff the next ready task, precise files, commands and remaining risks.

Acquisition/analysis tasks validate artifact contents rather than invent unit tests. A task needing several independently reviewable changes must be split into named children before implementation.

## Evidence requirements

A verified row needs a fixture ID/hash, expected result, actual artifact, reproducible command, platform/PC version, fresh pass and review record. Geometry, serialized data and UI comparisons are separate. Use committed relative artifacts or immutable CI/job URLs. Filling JSON fields is not proof.

Row states: not_started, in_progress, blocked, implemented, verified. Implemented means code exists; verified needs the promised runtime/oracle checks and review. Blocked requirements remain in scope.

## Do not conflate evidence levels

Static observation; modern .NET compilation; native iOS compilation; iOS simulator execution; physical-device execution/performance; PC/iOS/PC interoperability are different results. Full compatibility requires the original PC application to reopen and regenerate the edited project. A byte edit or retained preview does not satisfy that.

Do not remove legacy GUIDs, fake geometry, stub UI actions, swallow errors, weaken assertions, treat service DTOs as local services, restore removed credentials or claim live supplier operations identical offline. Required unresolved behavior blocks parity sign-off.

## Reusable handoff prompt

Read AGENTS.md and CURRENT_STATE.md. Run scripts/porting.cjs next, select one ready task, inspect its source/evidence and execute one reviewed failing-test-to-fix cycle. Preserve recovered snapshots and D:-scoped caches. Update affected rows with actual evidence. Report the commit, exact commands, fixtures, results and blockers. Do not claim overall completion.
