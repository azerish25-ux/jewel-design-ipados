Recommendations / acceptance criteria
1. Fail closed for any unsupported record version, wrong type GUID, mismatched expected identifier, malformed lengths/counts/strings, nonfinite number, or payload not consumed exactly to the CRC boundary. In particular do not assume current writer version 3.0 describes this legacy 1.1 node.
2. Preserve the source sample. Write copies only in reference/file-proof. Allow differences only in the selected eight-byte double and its four-byte leaf CRC; exact byte equality everywhere else is stronger evidence than field-only comparison.
3. Require all 241 node CRCs and the graph directory CRC to validate before and after editing. The graph CRC scope is empirical for this file and excludes nested records; preserve it only after verifying that scope against the original and edited bytes.
4. Independently re-read the saved bytes with a separately implemented reader and CRC routine, not an in-memory editor object or imported editor functions. Compare structural counts, GUID order, target layout and values, length, and changed-byte ranges.
5. Include unchanged-copy byte identity, reverse edit to original value restoring byte identity, and a stale/corrupted leaf CRC rejection. A malformed/truncated input rejection is useful additional boundary coverage.
6. Report unknown node bodies, preview images, geometry/native data, and all unedited sections as opaque preserved bytes. Preservation does not establish their semantic validity.
7. Name the result a bounded file-format edit/save/re-read proof. It is a library CSG experiment, not a portfolio CSP workflow, full serializer, application save/reopen, or geometry/preview refresh. The recovered modern managed serializer can upgrade versioned fields and mutate metadata during reads, so our preserved legacy record is not proof of identical application serialization behavior.
